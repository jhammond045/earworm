# Stage S4: live play

Built Nov 21, 2026, from [synth.md](synth.md) "Build plan > S4". The Sound panel has a Perform view: a MIDI device plays the selected layer (or the layer set for its channel), Learn maps any controller to a value or a macro, and on-screen keys, an XY pad, the macros and stand-ins for the mod wheel, bend and pressure play without one. Scenes morph a layer to one of its states.

## What was built

| Part | Where |
| --- | --- |
| Web MIDI input. Notes play the selected layer, or the layer set for their MIDI channel; MIDI note 60 is C4 (4800 cents); velocity is kept. On a beat layer notes 36, 38, 42 and 46 (General MIDI kick, snare, closed and open hat) play kit slots 1 to 4; other notes play nothing there. Notes held on a device that goes away are let go. | `web/src/perform/midi.ts`, `web/src/app/perform.ts` |
| Mod wheel (CC 1), pitch bend and channel pressure go to `MSG_SET_PERF` for the layer the channel plays. They are sources only: they move what routes take from them. | `perform.ts` |
| Learn: press Learn, touch a control (a Perform or Simple macro, or any slider in the Patch view; a keyboard focus counts as a touch), move a controller. A controller then sets that value outright in the state being edited; the engine hears it at once and it is committed as one undo step ("Controller") after 500 ms of rest. Learning a controller again moves it; Forget removes it. | `perform.ts`, commands `learnMidi`, `forgetMidi` |
| The map is kept with the project (`perform.map`: device name, channel, controller, layer and key). The last map learned for a device is also kept in settings (`midi:<device name>`, layers by position) and is used by any project that has no map for that device. | `types.ts`, `commands.ts`, `toDefault` and `mappedTarget` in `midi.ts` |
| Which layer each MIDI channel plays (`perform.channels`; empty means the selected layer), and what the XY pad moves (`perform.xy`), in the project. Removing a layer clears what pointed at it. | commands `setPerform`, `removeLayer` |
| Perform view: layer, Listen, Arm (Live follow without recording, a session setting like Listen), the MIDI devices or Connect MIDI, Learn; meters for the sung volume, intensity, hardness and pitch; keys (an octave with octave down and up) or four kit pads; the eight macros; mod wheel, bend (springs back to centre when let go) and pressure; the XY pad with its two targets (any value of the layer or a macro), by pointer or arrow keys; scenes; the learned map; the channel table; the main-thread timing of MIDI notes. | `perform.ts`, `web/index.html`, `style.css` |
| Scenes: `MSG_MORPH_TO` (layer, state, ms). The layer morphs from where it is to that state over the layer's scene time (`sceneMs`, 400 ms by default, set in the view) and stays there. While the transport plays a clip with morph markers the markers win; when it stops, or the clip has none, the scene holds. Without a tap, nothing changes from before. | `Layer::morph_to`, `scene_tick` in `crates/klont/src/layer.rs`; `update_morph` in `engine.rs` |
| A played note's shaped noise now starts with the note. The noise bank runs once per layer per control tick, so a kit slot that sounds only through it (a closed hat, for one) started one tick (32 samples) after a note from the ring. Notes played live now move the bank inside the tick they start in; song playback is unchanged, so golden renders stay as they were. | `Layer::noise_now`, `ShapedNoise::retarget` in `layer.rs` |
| A benchmark scene for listening layers. | `bench --listen` in `crates/klont/src/bin/bench.rs` |

| `cd web && npx vitest run src/perform/midi.test.ts` | Check 3 (a Learn mapping, the channel table and the scene time survive the journal replay of a reload and a project zip export and import), the MIDI message reader, kit notes, channels, device defaults |

The virtual source used here is a 60-line Swift program on CoreMIDI (`MIDISourceCreate`), outside the repository; any virtual MIDI port the OS offers (the IAC driver on macOS) works the same way. Chrome asks before a page may use MIDI; the runs below used a fresh profile with the permission granted ahead.

### Check 1 in detail

Each run: open the app, load a demo, Start, Perform view, Play (the demo loops), then the virtual source plays 300 notes over 30 s (10 a second, each held 60% of its slot, with a pitch-bend sweep and a sweep of controller 74 beside every note). The delay is `performance.now()` just after the note's control-ring write minus the event's `timeStamp`, which Chrome sets from the CoreMIDI packet's time; the source stamps every packet when it sends it, so the figure is OS delivery plus everything on the main thread up to the write. Headless Chrome, shared mode (SharedArrayBuffer ring), 48 kHz.

| Demo playing | Learn | Median | 95% | Worst | Load (1 min) |
| --- | --- | --- | --- | --- | --- |
| Melody | no | 0.31 ms | 0.75 ms | 10.88 ms | 3.0 |
| Beat | no | 0.35 ms | 3.59 ms | 7.41 ms | 2.2 |
| States | no | 0.27 ms | 1.20 ms | 5.64 ms | 2.6 |
| States | controller 74 learned to a macro at the start, then moving it every 100 ms | 0.33 ms | 1.92 ms | 68.66 ms | 3.2 |
| Melody (second series) | device default in use | 0.36 ms | 1.45 ms | 9.80 ms | 4.5 |
| Beat (second series) | device default in use | 0.25 ms | 1.24 ms | 4.04 ms | 3.8 |
| States (second series) | device default in use | 0.38 ms | 2.34 ms | 45.39 ms | 3.4 |
| States (second series) | learned again | 0.39 ms | 1.72 ms | 6.77 ms | 4.1 |

In the second series every project had the device default from the first series' Learn, so controller 74 was moving the bright macro (and committing it) all through those runs too. The worst cases are single notes that arrived while the main thread was busy with something else (the 68.66 ms one with the Learn commit itself); the 95th percentile is well inside 5 ms in every run.

"The demo song" is the M1 eight-layer song, which the app cannot open; the runs use the app's three demos. The song's weight lands on the audio thread, while this check is about the main thread, whose work during playback (meters, timeline, panels) is the same for any song.

### Check 2 in detail

`bench --listen`: a sung "ah" at 220 Hz with a 2 Hz swell goes in through `process` in 128-sample blocks; three melody layers hold a note, each with a layer route from its sung volume to its filter cutoff. The scene asserts that layer 0's sung volume comes from the mic when it listens and not otherwise. Best of 3 runs of 20,000 blocks.

| Run (load) | Live tier alone | None listening | One | Three |
| --- | --- | --- | --- | --- |
| 1 (5.5) | 35.1 µs | 46.7 µs | 46.6 µs | 46.9 µs |
| 2 (5.4) | 35.8 µs | 47.0 µs | 47.0 µs | 47.1 µs |

The engine reads the live tier's frame once per control tick and hands it to every listening layer (`engine.rs`, `tick`); a listening layer costs only its own routes.

### What still needs a real device

- The delay before the browser sees a message: USB or Bluetooth transfer and the device's own scanning. The event's `timeStamp` starts after that, so check 1 never includes it.
- How a real keyboard's knobs and faders feel through Learn, including controllers that send 14-bit pairs (CC n and n+32) or relative values; both are read as plain 7-bit values today.
- Device names across reconnects and across two identical devices: the map and the default are keyed by the name the browser gives.
- Safari on a Mac and on iOS, and the permission prompt in an ordinary Chrome or Firefox profile. Safari still has no Web MIDI (checked for this stage); `?nomidi=1` stands in for it in Chrome.

## Where the build differs from the design

- **Perform is a view of the Sound panel**, beside Simple, Patch and Mod, not a main view. On a wide screen the three main panels show at once, so a fourth would not fit; on a phone it is one tap further away.
- **Scenes are session state.** Which scene was tapped is not saved, and a new patch (a structure edit) drops it. The scene time is saved with the layer. The morph is a straight line from where the layer is.
- **Controllers write the state being edited**, as the on-screen knobs do, whichever scene is playing.
- **The mod wheel (CC 1) cannot be learned**: it is always the wheel source. Level and pan cannot be learned either; every value of the patch (route amounts included) and the eight macros can.
- **The device default is the last map learned for that device**, saved whenever Learn finishes; there is no separate "save as default", and a project uses it only while it has no map of its own for that device.
- **MIDI keys play the raw pitch**: the layer's Tune octave is not applied, as with the other on-screen notes (Hold note, Hear slot).
- **The engine part of check 1 is measured in the engine**, not in the browser: the ring is read at the start of every quantum, which the AudioWorklet calls once per quantum.
- **The noise fix**: see "What was built". It was found by check 1 and applies only to notes played live.
- **`?nomidi=1`** hides Web MIDI from the app, to check the page without it in a browser that has it.
