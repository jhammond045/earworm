# Stage S1: the engine runs patches

Built Nov 21, 2026, from [synth.md](synth.md) "Build plan". Nothing the user hears or sees should change: every layer plays the classic patch, which is today's Klont chain written as modules and routes.

## What was built

| Part | Where |
| --- | --- |
| Module table: the 96 old parameters stay as the Klont vocabulary, eight new descriptors, and each module type's parameters. `pnpm gen:params` also writes the Rust and TypeScript module tables. | `crates/params/modules.toml`, `crates/params/src/modules.rs`, `web/src/gen/modules.ts` |
| Compiled patch format (`LOAD_PATCH`) and its checks: counts, caps, types, cables only forward (no cycles), value ranges. A bad patch is refused with `LOAD_MALFORMED` and the old one keeps playing. | `crates/klont/src/patch.rs` |
| Voice split into modules run in program order over each span: partial bank, amp, click, clang, fold, comb, filter; envelopes and LFOs as modulation sources. | `crates/klont/src/modules.rs`, `voice.rs` |
| Route evaluator: source, shaper (range, bend, points, smoothing, latch, polarity), amount, group depth, via; add, scale and pull. | `voice.rs` (per voice), `layer.rs` (layer routes: the macros) |
| Value vector per layer (up to 1,024 values), morph, Influence, layer routes, smoothing; the channel chain. | `layer.rs` |
| Layer blob v2, states blob v2, sample pool (`LOAD_SAMPLE`, 2^23 floats shared by every layer). | `protocol.rs`, `samples.rs`, `grain.rs` |
| The classic patch in Rust (every layer starts on it; Rust tests, the benchmark and the analysis tests build sounds with it) and in TypeScript (the document's patch). A test checks both compile to the same blob. | `crates/klont/src/classic.rs`, `web/src/synth/classic.ts`, `web/src/synth/fixtures` |
| Patch types, layout and compiler; v2 blob encoders. | `web/src/synth/patch.ts`, `web/src/m1/blobs.ts`, `web/src/project/compile.ts` |
| Schema 4: a layer has a `patch`, a state has `values` by key, a kit slot keeps its pitch, a note has `vel`. Migration from schema 3 converts each layer to the classic patch and starts a fresh undo history; the app says so when it opens or imports such a project. | `web/src/project/types.ts`, `migrate.ts`, `persist.ts`, `archive.ts` |
| Factory presets: the ten sounds of `m2/sounds.ts` as preset files of the classic patch. The Preset menu still builds sounds from `sounds.ts`; loading presets from files arrives with preset save and load in S3. | `web/src/presets/` (`pnpm gen:presets`) |

## How to check it

| Command | What it checks |
| --- | --- |
| `pnpm test` | Every Rust and TypeScript test, including the no-allocation test (it now loads a patch, a layer, states and a sample while armed) and the golden renders |
| `cd web && npx vitest run src/golden` | Golden renders: the fixture projects on the engine from before S1 against the same projects migrated and rendered now |
| `cargo run --release -p klont --bin bench` | Benchmark: worst case per budget, then the demo song |
| `cargo test -p analysis --release --test blind_match --test round_trip -- --nocapture` | Influence scores |

The golden fixtures (`web/src/golden/fixtures`) were recorded from the engine before any S1 change: five projects made through the document commands (three with takes captured by the live engine from a synthetic voice and placed as the app places them), the app's three demos and the M1 demo song. `klont-reference.wasm` is that engine. The five projects were built by a script with the app's own commands and saved with its export code, not saved by hand in a browser.

## Where the build differs from the design

The classic patch has to sound as it did, and a few of today's maps could not be written exactly as synth.md describes routes. Each change below is in the code and keeps the design's shape.

- **Envelopes have a mode** (`env.mode`): ADSR, decay (starts at full; while the first envelope releases, the release adds to the fall) and one-shot (starts at full, ignores note-off). Today's amp, noise and pitch envelopes are one of each; no single envelope type reproduced all three.
- **Pull routes move the target in its real units** toward the source value (the hit's attack in seconds, as the old map did), and a latched pull holds what it set at note start. synth.md has pulls in the normalized domain, which changed the attack of every hit with Follow below 1.
- **A route into another route's amount** adds in that amount's units, by the source value (the hit's bend deepens the pitch envelope in semitones).
- **An octaves target** (`oct:<key>`) moves a log-scaled value after mapping, so the LFO filter sweeps can still reach past 20 kHz up to the filter's limit, as before.
- **Level and pan sit between the mono effects and the first stereo effect**, not at the end of the channel: moving them would change every panned layer with delay or reverb. Level and pan also stay layer fields rather than values for now; making them values belongs with automation (S5).
- **A patch carries a starting value per key** (`Patch.defaults` in the document, the init words of the blob), and **may give a key another descriptor** (`Patch.descs`), so the classic patch keeps the old parameters' ranges and old values map over unchanged.
- **Routes carry a `unit`**: target units per unit of amount. A fixed constant of the old maps (a gesture amount, a macro weight) rides there with amount 1, which keeps it exact; synth.md's "amount 2W" for macro routes would have doubled the macros.
- **Smaller rules**: a stored hold at its minimum (0.5 ms) is off whatever routes add, as before; values that only note-start routes move start from their real value mapped back; the drift LFO keeps the old chaos seed; the grain source sent per layer stays capped at 10 s.
- **Not in S1**: route outputs and intensity in the meter block, layer LFOs and layer features as sources, channel filter, `osc`, `noise`, `sampler` (all S2 or S3). The engine refuses those types today.
