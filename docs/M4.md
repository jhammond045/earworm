# M4: Influence and states

M4 builds Influence and states from the [TDD](TDD.md) build order: the instant and live match over the full parameter table, the grain source ("use the sound itself"), "use my sound for a kit slot", state slots and the morph lane. It builds on the M3 track page. Its gate is **blind match 70% at 100%**:

- In a blind four-way test, listeners pick the source a match was made from at least 70% of the time, across 20 varied source sounds, with Influence at 100% (PRD gate; TDD testing table, Influence row). This is the M0 blind test, now on the klont engine with the full parameter table, the grain cloud and the live match.

This page says how to run it, how to judge the gate on the reference laptop (2020 M1 MacBook Air, Chrome), what is built and what was measured on the build machine.

## Run it

```sh
pnpm install
pnpm dev
```

Open the URL Vite prints. The index page has a new M4 section:

- **`m4-test.html`, the blind match test** (the gate). Sources, match and listen, blind trials. It shares saved sources with the M0 Influence pages: anything saved on `influence.html` appears here, and the other way round.
- **`m3.html`, the track page** (now titled "Earworm: Track"), with a new **Sound states and Influence** section and a morph lane under every timeline lane:
  - **Sound states:** up to 8 per layer. Add, Duplicate, Remove, rename, and pick the state you are editing; the sound preset, the 8 macros and the Influence amount apply to that state.
  - **Influence:** choose a source file (or drop one), pick one of the M0 page's saved sources, or hold **Listen** (or the L key) and make a sound into the mic. While you hold Listen the match reruns every 250 ms on what it has heard so far and the layer's sound moves with it; a readout shows the five aspect groups and a few named parameters, and says "provisional" while motion is still uncertain. On release the match runs once over the whole sound and becomes the layer's Influence. Then: **Amount** (0 to 100%), the aspect toggles **Tone, Shape, Motion, Grit, Space**, **Use the sound itself** (the grain cloud plays the source's steady region), **Commit** (writes the blend into the state and clears the Influence), **Clear**, **Hold to play a note** and **Play source**.
  - **Use my sound for a kit slot** (beat layers): pick a slot, then record one hit or choose a file. The hit is matched with the decaying-sound rows on and becomes that slot's sound; a pitched hit also sets the slot's pitch.
  - **Morph lane:** a thin strip under each lane. Double-click it to add a marker for the state you are editing, drag to move, click to select, Delete to remove; the selected marker's state, shape (line, ease, late, step, wobble), length and time are editable. M adds a marker at the playhead, `[` and `]` step through markers, the arrow keys nudge. As the track plays, the layer's sound moves from state to state along the lane.

Tests: `pnpm test` (Vitest, then `cargo test --workspace`). The gate's objective stand-in:

```sh
cargo test -p analysis --release --test blind_match -- --nocapture
```

Other M4 commands:

| Command | What it does |
| --- | --- |
| `cargo test -p analysis --release --test round_trip -- --nocapture` | Renders known klont sounds and checks the match recovers their parameters |
| `cargo test --release -p klont --test m4 grain_cost -- --ignored --nocapture` | Worst-case cost of the grain cloud: every layer with a full cloud |
| `cargo run --release -p klont --bin bench` | The M1 benchmark; a layer with no grain source costs nothing extra |

## Judge the gate

The gate needs people listening. The best test has several listeners who did not choose the sources.

### 1. Collect 20 sources

1. Run `pnpm dev`, open `http://localhost:5173/m4-test.html` in Chrome on the 2020 M1 MacBook Air.
2. Under **1. Sources**, drop audio files on the page or press **Record 3 s from mic** (the mic is used only when you press it). Aim for 20 varied sounds, 0.5 to 3 s each: voice, whistle, flute-like, plucked string, bell, drum, clap, hiss, synth pad, bowed sound, and so on. Sources saved earlier on `influence.html` are already listed.
3. Press **Match and render all** under **2. Match and listen**. Each source is matched and rendered through the klont engine offline with Influence at 100% on a neutral sound. Match and render times are shown per source.
4. Listen to a few with **Play source**, **Play match** and **Play A then B**. "Use the sound itself" is on by default for unpitched sounds; the selector also has "off for all" and "on for all" so you can hear what the grain cloud adds. The gate run uses **default rule**.

### 2. Run the blind test

1. Under **3. Blind test**, note or set the **Seed** and press **Start**. Each trial plays one match and four candidate sources, A to D; pick the one the match was made from. Listen as often as you like.
2. A run is one trial per source, in shuffled order (20 trials for 20 sources). The score is shown against 70%, with per-source results. Twenty trials is a small sample: a second run with another seed, or another listener, makes the figure firmer.
3. Press **Download JSON**. It records the seed, the sources, every pick and the settings, and marks the run as a gate run only with the default rule and 20 or more sources.
4. Ideally have two or three other people run it with the same seed.

**Pass:** 70% or more correct across 20 varied sources.

### 3. Influence on the track, by ear (not part of the gate)

1. Open `m3.html`, press **Start (audio and mic)**, wired headphones on. Draw or capture a melody on the Melody layer and press Play.
2. Hold **Listen** and make a sound (a whistle, a buzz, a breathy "hhh"). The melody's sound should move toward it while you hold, several times a second.
3. Sweep **Amount** from 0 to 100% and toggle the aspects. Turn on **Use the sound itself** for a noisy source. **Commit**, then undo.
4. Add a second state, change its sound, put two markers on the morph lane and play: the sound should move between the states without clicks.

## What was measured on the build machine

Build machine: Apple M4 MacBook Air, Chrome 154 headless for the pages, 48 kHz. No one listened: the blind test needs people, so the gate figure below comes from an objective stand-in with synthetic sources.

### Blind match, objective stand-in

`crates/analysis/tests/blind_match.rs`. 20 synthetic sources made with code that is not the klont engine (Karplus-Strong pluck, bowed sawtooth with vibrato, flute, clarinet-like, organ, voice "aa", whistle, bell, marimba, gong, kick, snare, hi-hat, clap, hiss, wind, synth pad, distorted guitar, tremolo sine, reversed swell), 0.75 to 2 s each. Each is matched with `match_full` and rendered by the klont engine offline with the match as the Influence target at 100% on a neutral sound. The "listener" is the TDD's Refine loss (log-mel spectrogram distance at three transform sizes plus loudness envelope distance): in each of 5 seeded trials per source it picks the nearest of the true source and 3 others.

| Run | Correct |
| --- | --- |
| Matched, default rule for "use the sound itself", with the grain cloud (the gate setting) | **84 of 100 = 84%** |
| Matched, grain cloud on for every source | 86% |
| Matched, synthesis only (no grain cloud) | 82% |
| Neutral sound, no match (what the test gives for nothing) | 25% (chance is 25%) |
| Second draw (other source and trial seeds), default rule | 79% (neutral 20%) |

Per source at the gate setting: 5 of 5 for 15 sources, 4 of 5 for the pluck, bowed saw and reversed swell, and three misses: the bell (0 of 5, read as harmonic), the gong (1 of 5, matched as noise) and the wind (1 of 5, a drifting low-pass).

**Read this with care.** The judge is a spectral distance, not a person, and the match was tuned while watching this test (the second draw guards a little against that). A distance that picks the right source does not prove a listener will. Treat 84% as evidence the match captures the gross character of a sound, not as the gate. The gate is the listening test above.

### Match quality against the engine itself

`crates/analysis/tests/round_trip.rs` renders klont sounds with known parameters and measures them back (15 tests). Recovered within: pitch 5 cents; tilt 0.5 dB/oct; odd-even 0.1; harmonic against noise mix 25%; noise band shape 3 dB rms; attack 25%, decay 30%, sustain 0.08, release 35%; modal 0.3 and damp 0.15 on a struck bar; pitch drop 2 semitones and 20 ms; vibrato rate 0.5 Hz and depth 25%; tremolo depth 0.1; click 0.1 to 0.15; reverb size 0.07 and mix 0.2. Chaos is found as chaos (0.4 to 1.0 at a true 1.0). Fold reads weakly (about 0.25 at a true 1.0). Crush is not read back.

### How it works

- **Influence is resolution step 2,** as built in M1: the layer blob carries the target, the aspect mask and the amount. M4 fills the target from the full match and sends it.
- **The match** measures the source the way the TDD's instant-match table says, then converts each measurement into the klont engine's terms. The conversions (release and attack time constants, noise-to-partial level, the decay of the fundamental when partials die at different rates, bands above the highest partial) were calibrated by rendering klont sounds and measuring them back. Unpitched sources (under 30% voiced) skip the harmonic rows and turn on "use the sound itself" by default.
- **Use the sound itself** stores the source in the project as a `grain-` blob and gives the engine its steady region (the longest stretch within 6 dB of the loud part's median, 0.1 to 10 s) with its reference pitch. The target's grain mix goes up and the partial and noise mixes down in proportion.
- **Live match** is the lazy version of the TDD's running estimators: every 250 ms the worker reruns the whole match on everything heard so far, and the new target goes to the engine as control messages, where parameter smoothing turns the steps into glides. Its cost grows with the length of the capture (the spectral work is capped, the loudness and pitch passes are not); running sums would remove that, if long Listens turn out slow.
- **States and morph.** A layer with two or more states, or with markers, gets a states blob. Each control tick the engine finds the layer's clip position, takes the newest marker at or before it and blends from the previous marker's state with that marker's shape over its length, then runs Influence and macros on the blend. Smoothing after that means a morph never clicks. A layer with one state and no markers works exactly as in M3.
- **Kit slot from a sound** runs the same match with the decaying-sound rows (modal, damp) on, and writes the result into that slot.
- **Schema 2.** Opening a schema 1 project upgrades the snapshot, the undo history and the journal entries with the same step before replaying, then writes the upgraded snapshot back, so old and new entries never mix.
- **No automatic mute.** Listen and kit-hit recording use the mic only while the button is held. Nothing checks the mic for the engine's own sound.

### What came from M0 to M3

- **Kept:** every earlier page. `m3.html` keeps its URL and its M3 gate panel.
- **Changed, M0 Influence pages:** the envelope fit shared with the M0 match got fixes found while calibrating (attack read at the first 90% point, a plateau followed by a release no longer read as one long decay, the release measured from the plateau, the fundamental's own decay when damp is measured). M0 matches of such sounds will differ a little. M0's Save now keeps sources other pages saved instead of replacing the whole set.
- **Changed, engine:** two new blob kinds, a v2 track blob (v1 still loads and the compiler writes v1 when there are no markers), 30.7 MB of grain buffers allocated at start (two 10 s buffers per layer, so the audio thread never allocates).
- **Fixed:** the host refused blob kinds above 3, so grain and states could not reach a live engine.

## Not in M4, on purpose

- **Refine (CMA-ES search):** v1, per the TDD.
- **Stereo sources.** Sources are mixed to mono; width is never matched.
- **Level matching on the blind test page:** a match and its source are not loudness-matched before playing.
- **Running-sum live match** (see How it works).
- **The LLM sound endpoint** (`/api/sound`): later.
- **Deleting unused grain sources.** They stay in the project so undo can bring them back; cleanup belongs with M5 storage work.

## Known limits

- **Bells, gongs and slowly moving filtered noise match poorly** in the stand-in: inharmonic partials are read as harmonic, a dense gong as noise, and a drifting low-pass is not followed.
- **A fast pitch sweep (a kick) reads as unpitched,** so it plays from the grain cloud at C4 rather than as a pitched drop.
- **Fold reads weakly and crush not at all.**
- **Motion parameters are often provisional** on sources under 2 s: two cycles of a slow LFO need time.
- **Live controls on a layer with states:** the engine's states take over the base, macros and Influence amount, so preview drags on such a layer go through the compiler rather than straight control messages.
- **A full 32-grain cloud drops new grains,** and a second source change within 50 ms of the first can click.
- **Morph lengths** are converted at the tempo when the marker is reached; a tempo ramp inside a morph is not followed exactly.
- **Sharing sources across pages:** if `influence.html` and `m4-test.html` are open at the same time, the last one to save wins for sources with the same name.
